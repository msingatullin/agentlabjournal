Асинхронный генератор корпоративной брошюры на FastAPI с потоковой выдачей

Генерация корпоративной брошюры по сайту состоит не только из запроса к языковой модели. Нужно получить HTML, удалить навигационный шум, выбрать полезные страницы, ограничить объём контекста и показать пользователю результат без долгого ожидания. В этой статье соберём такой конвейер на FastAPI.

Под HTML-очисткой будем понимать удаление из страницы элементов, которые не помогают описать компанию: меню, формы, скрипты, стили, футеры и повторяющиеся служебные блоки.

Что будем строить

Сервис принимает URL сайта и возвращает поток текста. Конвейер выглядит так:

  1. проверяет URL и ограничивает область обхода исходным доменом;
  2. загружает главную страницу и извлекает ссылки;
  3. отбрасывает ссылки по расширению, якорю, протоколу и очевидному шуму;
  4. вторым этапом ранжирует оставшиеся страницы по полезности;
  5. очищает HTML и обрезает текст до заданного бюджета;
  6. передаёт контекст модели через асинхронный клиент;
  7. отдаёт токены пользователю через StreamingResponse;
  8. переключается на резервный провайдер при ошибке основного.

Пример ниже показывает архитектуру и ключевые фрагменты. Названия моделей, адреса провайдеров и лимиты являются настройками примера, а не утверждением о доступности конкретного сервиса.

Зависимости и безопасный запуск

Создайте отдельное окружение и установите минимальный набор библиотек:

python -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
pip install fastapi uvicorn httpx beautifulsoup4 lxml openai pydantic-settings

Секреты не следует хранить в исходном коде. Используйте переменные окружения:

export OPENAI_API_KEY="замените-на-ключ-в-локальном-окружении"
export FALLBACK_API_KEY="замените-на-резервный-ключ"
export PRIMARY_MODEL="модель-основного-провайдера"
export FALLBACK_MODEL="модель-резервного-провайдера"

В рабочей среде ключи лучше передавать через секрет-хранилище или менеджер переменных окружения. Не добавляйте файл с секретами в систему контроля версий.

Модель настроек

Настройки вынесем в отдельный объект. Это упрощает тестирование и замену провайдера:

from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    primary_api_key: str
    fallback_api_key: str | None = None
    primary_model: str = "primary-model"
    fallback_model: str = "fallback-model"
    max_pages: int = 8
    max_chars_per_page: int = 8000
    request_timeout: float = 15.0

    model_config = SettingsConfigDict(
        env_prefix="",
        env_file=".env",
        extra="ignore"
    )

settings = Settings(
    primary_api_key=os.environ["OPENAI_API_KEY"],
    fallback_api_key=os.getenv("FALLBACK_API_KEY")
)

В реальном приложении можно позволить BaseSettings читать переменные автоматически. Важно, чтобы значения лимитов имели консервативные значения по умолчанию.

Загрузка и очистка HTML

Для сетевых запросов используем httpx.AsyncClient. Таймаут, ограничение размера ответа и проверка домена нужны до передачи данных модели. 

from urllib.parse import urlparse
import httpx
from bs4 import BeautifulSoup

async def fetch_html(url: str) -> str:
    timeout = httpx.Timeout(settings.request_timeout)
    headers = {"User-Agent": "AgentLabJournalBot/1.0"}

    async with httpx.AsyncClient(
        timeout=timeout,
        follow_redirects=True,
        headers=headers
    ) as client:
        response = await client.get(url)
        response.raise_for_status()

        content_type = response.headers.get("content-type", "")
        if "text/html" not in content_type:
            raise ValueError("URL не содержит HTML-документ")

        raw = response.content
        if len(raw) > 2_000_000:
            raise ValueError("HTML-документ слишком большой")

        return raw.decode(response.encoding or "utf-8", errors="replace")

def clean_html(html: str) -> str:
    soup = BeautifulSoup(html, "lxml")

    for tag in soup([
        "script", "style", "noscript", "svg",
        "nav", "footer", "form", "aside"
    ]):
        tag.decompose()

    text = soup.get_text(" ", strip=True)
    return " ".join(text.split())

Этот очиститель намеренно простой. Он не понимает смысл страницы и может удалить полезный блок, если сайт использует нестандартную структуру. Для конкретного домена обычно стоит добавить селекторы основного содержимого.

Двухэтапная фильтрация ссылок

Одного условия «ссылка ведёт на тот же домен» недостаточно: оно пропустит страницы поиска, календари, PDF-файлы и повторяющиеся URL с параметрами. Поэтому применим два этапа.

Этап 1: техническая фильтрация

from urllib.parse import urljoin, urldefrag, urlparse

SKIP_EXTENSIONS = (
    ".pdf", ".jpg", ".jpeg", ".png", ".gif",
    ".zip", ".doc", ".docx", ".xls", ".xlsx"
)

SKIP_PARTS = (
    "/login", "/cart", "/search", "/tag/",
    "/author/", "/feed"
)

def same_site(candidate: str, root: str) -> bool:
    return urlparse(candidate).netloc == urlparse(root).netloc

def technical_filter(href: str, root: str) -> str | None:
    absolute = urljoin(root, href)
    absolute, _ = urldefrag(absolute)
    parsed = urlparse(absolute)

    if parsed.scheme not in {"http", "https"}:
        return None
    if not same_site(absolute, root):
        return None

    path = parsed.path.lower()
    if path.endswith(SKIP_EXTENSIONS):
        return None
    if any(part in path for part in SKIP_PARTS):
        return None

    return absolute.rstrip("/")

Этап 2: смысловой отбор

После технического фильтра можно оставить несколько страниц, путь которых похож на корпоративные разделы: about, company, services, products, contacts. Остальные ссылки не обязательно удалять сразу — их можно добавить после приоритетных. 

PRIORITY_WORDS = {
    "about": 5, "company": 5, "services": 4,
    "products": 4, "solutions": 4, "contact": 3,
    "contacts": 3, "team": 2
}

def score_url(url: str) -> int:
    path = urlparse(url).path.lower()
    return sum(weight for word, weight in PRIORITY_WORDS.items()
               if word in path)

def select_links(html: str, root: str, limit: int) -> list[str]:
    soup = BeautifulSoup(html, "lxml")
    candidates = {
        item for link in soup.find_all("a", href=True)
        if (item := technical_filter(link["href"], root))
    }

    ranked = sorted(candidates, key=score_url, reverse=True)
    return ranked[:limit]

На практике полезно добавить нормализацию завершающего слеша, удаление трекинговых параметров и ограничение глубины обхода. Не обходите весь сайт без лимита: это повышает стоимость, время ответа и риск попасть на бесконечные URL.

Контроль контекста

Даже несколько страниц могут превысить допустимый контекст модели. Поэтому зададим общий бюджет символов и будем сохранять источник каждого фрагмента. Это помогает отлаживать итог и не смешивать данные разных страниц. 

def build_context(pages: list[tuple[str, str]]) -> str:
    chunks = []
    remaining = settings.max_chars_per_page * settings.max_pages

    for url, text in pages:
        if remaining <= 0:
            break

        fragment = text[:min(settings.max_chars_per_page, remaining)]
        chunks.append(f"ИСТОЧНИК: {url}\n{fragment}")
        remaining -= len(fragment)

    return "\n\n---\n\n".join(chunks)

Лимит в примере измеряется в символах, а не токенах. Это простая защитная граница, но точное планирование контекста требует токенизатора конкретной модели.

Асинхронный LLM-клиент и резервный провайдер

Клиент основного провайдера создадим один раз на запрос генерации. Резервный клиент должен иметь совместимый интерфейс или отдельный адаптер. Важно переключаться только на ошибки, при которых повтор действительно имеет смысл: сетевой сбой, таймаут или временная ошибка провайдера. 

from openai import AsyncOpenAI

def make_client(api_key: str, base_url: str | None = None):
    return AsyncOpenAI(api_key=api_key, base_url=base_url)

async def stream_with_fallback(messages):
    providers = [
        (make_client(settings.primary_api_key), settings.primary_model)
    ]

    if settings.fallback_api_key:
        providers.append(
            (make_client(settings.fallback_api_key), settings.fallback_model)
        )

    last_error = None

    for client, model in providers:
        try:
            stream = await client.chat.completions.create(
                model=model,
                messages=messages,
                temperature=0.2,
                stream=True,
            )

            async for chunk in stream:
                delta = chunk.choices[0].delta.content
                if delta:
                    yield delta

            return
        except Exception as exc:
            last_error = exc

    raise RuntimeError("Все LLM-провайдеры недоступны") from last_error

Тип исключений в рабочем проекте следует сузить до известных ошибок SDK. Широкий Exception здесь показан только для компактности примера.

Потоковый endpoint FastAPI

StreamingResponse начинает отправлять данные, как только генератор получает первый фрагмент. Пользователь видит прогресс, а серверу не нужно собирать весь текст в памяти до ответа. 

import os
from fastapi import FastAPI, HTTPException
from fastapi.responses import StreamingResponse
from pydantic import AnyHttpUrl, BaseModel

app = FastAPI()

class BrochureRequest(BaseModel):
    url: AnyHttpUrl

async def collect_pages(root: str):
    home_html = await fetch_html(root)
    urls = select_links(home_html, root, settings.max_pages - 1)
    urls = [root, *urls]

    pages = []
    for url in urls:
        try:
            html = await fetch_html(url)
            pages.append((url, clean_html(html)))
        except (httpx.HTTPError, ValueError):
            continue

    if not pages:
        raise HTTPException(
            status_code=422,
            detail="Не удалось получить ни одной HTML-страницы"
        )

    return pages

@app.post("/brochure")
async def generate_brochure(payload: BrochureRequest):
    root = str(payload.url)

    async def output():
        pages = await collect_pages(root)
        context = build_context(pages)

        messages = [
            {
                "role": "system",
                "content": (
                    "Составь фактическую корпоративную брошюру на русском языке. "
                    "Не выдумывай сведения, которых нет в источниках. "
                    "Отмечай пробелы в данных."
                ),
            },
            {
                "role": "user",
                "content": (
                    f"Сайт: {root}\n\n"
                    f"Материалы сайта:\n{context}\n\n"
                    "Структура: краткое описание, продукты или услуги, "
                    "отличия, целевая аудитория, контакты и ограничения данных."
                ),
            },
        ]

        async for token in stream_with_fallback(messages):
            yield token

    return StreamingResponse(
        output(),
        media_type="text/plain; charset=utf-8",
        headers={"Cache-Control": "no-cache"}
    )

Для больших сайтов сбор страниц в этом варианте идёт последовательно. Это проще контролировать, но медленнее. Следующий шаг — ограниченный параллелизм через asyncio.Semaphore, чтобы не создавать чрезмерную нагрузку на сайт.

Проверка результата

Запустите приложение:

uvicorn app:app --reload

Проверьте потоковую выдачу из другого терминала:

curl --no-buffer \
  -X POST http://127.0.0.1:8000/brochure \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com"}'

Воспроизводимая проверка должна подтвердить: endpoint принимает только HTTP(S)-URL, ссылки за пределами домена не попадают в контекст, не-HTML-ответы отбрасываются, объём текста ограничен, а клиент получает фрагменты до завершения всей генерации. Адрес example.com здесь служит учебным примером, а не источником фактов для брошюры.

Типовые ошибки

  • Весь текст сайта попадает в промпт. Добавьте очистку HTML, список приоритетных страниц и общий бюджет контекста.
  • Сервис обходит чужие домены. Проверяйте netloc после разрешения относительных ссылок.
  • Поток не отображается в браузере. Проверьте, что генератор действительно выдаёт части текста, а прокси не буферизует ответ.
  • Резервный провайдер вызывается после любой ошибки. Разделите ошибки валидации, лимитов и временной недоступности.
  • Сайт блокирует запросы. Уважайте правила сайта, задавайте понятный User-Agent, ограничивайте частоту и не обходите защитные механизмы.
  • В брошюре появляются выдуманные сведения. Передавайте URL-источники в контекст и требуйте явно отмечать отсутствие данных.

Ограничения архитектуры

Это минимальная рабочая схема, а не полноценный краулер. Она не хранит кэш, не поддерживает очередь длительных задач, не извлекает данные из JavaScript-приложений и не гарантирует, что HTML содержит актуальную редакционную версию страницы.

Для production-сценария потребуются кэширование страниц, ограничение частоты запросов, SSRF-защита, проверка DNS и IP-диапазонов, наблюдаемость, идентификаторы задач, отмена клиентом и отдельное хранилище результатов. Также стоит очищать чувствительные данные до отправки в LLM и формально определить политику хранения URL и содержимого страниц.

Итог

Асинхронный генератор корпоративной брошюры на FastAPI с потоковой выдачей строится вокруг нескольких простых границ: сеть отвечает только за безопасную загрузку, BeautifulSoup — за очистку, фильтры — за отбор источников, контекстный сборщик — за лимиты, а LLM-адаптер — за генерацию и резервирование. Такое разделение облегчает замену провайдера и позволяет отдельно проверять каждый этап.
